# Phase 1.4 — 行情 / 快照层 设计

> 父路线图:`~/.claude/plans/dashboard-traking-ibkr-daily-activity-s-squishy-bee.md` 的「1.4 行情 Provider(最小实现)」。

## 目标

让 dashboard 能显示**真实市值、未实现盈亏、和一条真正的净值曲线**。M5 的 `pnl/curve.py` 已写好曲线数学,只差一个「每日组合价值」序列 —— Phase 1.4 把它喂进去。

不依赖任何实时 / 付费 API:行情走 Yahoo(`yfinance`,延迟 15–20 分钟,免费无 key)。

## 关键决定(已与用户确认)

- **回填历史(做法 B)**:`positions_snapshot` 是**可重建的缓存**(和 DB 其它表一样,文件账本才是真相源)。从账户第一笔成交回放到今天,每个交易日重建持仓快照 —— 导入完立刻能看到完整曲线。**不要常驻定时任务**,按需重建。
- **期权**:`yfinance` 没有可靠的历史期权价。所以股票 / ETF 用 yfinance 历史收盘价(准);**期权按成本计**(快照里 market_* 留空,曲线聚合时按 `quantity × avg_cost` 计入)。期权平仓后的已实现盈亏由 M5 引擎照算,不受影响。期权持有期短,误差可控。
- 成交目前全是 USD,市值即 USD,**暂不接 FX**(M4 层已在,以后需要再接)。
- 范围:**只做后端**。前端页面、IBKR 实时(Phase 2)不在内。

## 1. `MarketDataProvider` 接口 — `app/services/providers/base.py`

```python
class MarketDataProvider(ABC):
    @abstractmethod
    def get_daily_closes(
        self, symbol: str, start: date, end: date
    ) -> dict[date, Decimal]:
        """`symbol` 在 [start, end] 每个交易日的收盘价。非交易日不出现在结果里。"""

    @abstractmethod
    def get_latest_close(self, symbol: str) -> Decimal | None:
        """最新一个收盘价;取不到返回 None。"""
```

价格一律 `Decimal`。USD。

## 2. `YahooFinanceProvider` — `app/services/providers/yahoo.py`

用 `yfinance` 实现 `MarketDataProvider`。`yfinance` 的网络调用是唯一不可测的接缝,所以构造函数注入一个 fetch 函数,测试传假的、离线跑:

```python
class YahooFinanceProvider(MarketDataProvider):
    def __init__(
        self,
        history_fn: Callable[[str, date, date], dict[date, Decimal]] | None = None,
    ) -> None:
        self._history_fn = history_fn or _yfinance_history

    def get_daily_closes(self, symbol, start, end) -> dict[date, Decimal]:
        return self._history_fn(symbol, start, end)

    def get_latest_close(self, symbol) -> Decimal | None:
        closes = self._history_fn(symbol, date.today() - timedelta(days=7), date.today())
        return closes[max(closes)] if closes else None
```

`_yfinance_history(symbol, start, end)`:模块级函数,调 `yfinance.Ticker(symbol).history(start=, end=)`,把返回的 DataFrame 的 `Close` 列转成 `dict[date, Decimal]`(价格经 `str()` 转 `Decimal`,避免 float 污染)。这是唯一真正打网络的地方。

`yfinance` 加进 `pyproject.toml` 的 `dependencies`。

## 3. 快照构建器 — `app/services/snapshot/builder.py`

```python
def rebuild_snapshots(
    session: Session, account: Account, provider: MarketDataProvider
) -> int:
    """重建 `account` 的 positions_snapshot,返回写入行数。

    账户级删 + 重插(幂等,可重建投影)。出错回滚。
    """
```

逻辑:

1. 删掉该账户已有的 `positions_snapshot` 行。
2. 取该账户全部 trades,按 instrument 分组(复用 `pnl/engine.py` 的 `_trades_by_instrument` 思路)。
3. 对每个 instrument:
   - 区间 = `[第一笔成交日, today]`。
   - STOCK / ETF:`provider.get_daily_closes(symbol, 第一笔成交日, today)`。
   - 对区间内**每个有收盘价的交易日 d**:用 FIFO 回放该 instrument 截至 d(含)的成交 → `quantity` / `open_cost_basis` / `avg_cost`(复用 M5 `fifo.run_fifo`)。
   - `quantity > 0` 才写一行 `PositionSnapshot`:
     - STOCK/ETF:`market_price` = d 当天收盘价;`market_value` = `quantity × market_price`;`market_value_usd` = 同值(USD);`unrealized_pnl` = `market_value − open_cost_basis`;`unrealized_pnl_usd` = 同值。
     - OPTION:`market_price` / `market_value` / `market_value_usd` / `unrealized_pnl` / `unrealized_pnl_usd` 全部 `None`(按成本计,无市场 mark)。仍写行,记录 `quantity` / `avg_cost`。
4. `quantity == 0`(已平仓)的日子不写行。

期权不调 provider(省网络)。一个 instrument 若 provider 一个价都没返回(下市 / 数据缺失)→ 跳过该 instrument 的市场定价,当作期权一样按成本计,不报错(数据源缺失是常态,不该让整次重建失败)。

`build_day_points` 对每个 `d`(= 快照行日期 ∪ 入金/出金日期 —— 每笔外部资金流都必须落在某一天上,曲线靠累加 `net_flow` 算累计净入金)。无快照的日子(周末、首笔成交之前)持仓市值从最近一次快照沿用(首次快照之前为 0):

- **持仓市值** `holdings(d)` = 该日所有 `PositionSnapshot` 行之和,每行取
  `market_value_usd`,为 `None`(期权 / 缺数据)时取 `quantity × avg_cost`。
- **现金余额** `cash(d)`:
  - `+ Σ cash_flows.amount_usd`(occurred_at ≤ d) —— 入金正、出金负、分红利息正、费用预扣负,符号已在数据里。
  - `+ Σ 成交现金影响`(executed_at ≤ d):BUY = `−(proceeds_usd + commission_usd)`,SELL = `+(proceeds_usd − commission_usd)`。
- `portfolio_value(d)` = `cash(d) + holdings(d)`。
- `net_flow(d)` = 当天 `DEPOSIT` 金额 − `WITHDRAWAL` 金额(`amount_usd`)。
- 产出 `DayPoint(on_date=d, portfolio_value=…, net_flow=…)`,按日期升序。

`compute_account_curve` 再调 M5 的 `compute_equity_curve(points, mode)`。

## 错误处理

- provider 取不到某 symbol 的数据 → 该 instrument 按成本计,不抛错(见 §3)。
- `_yfinance_history` 网络 / 解析失败 → 让异常上抛(调用方决定重试);快照构建器本身不吞网络错。
- 空账户(无成交)→ `rebuild_snapshots` 写 0 行,`build_day_points` 返回 `[]`。
